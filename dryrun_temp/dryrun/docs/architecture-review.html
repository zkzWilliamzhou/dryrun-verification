Architecture review - deepening opportunities

dryrun: two engines, four drifting policies

Scope: the two simulation engines are the hot spot of the last five commits (simulate/trace.py, 753 lines; simulate/sandbox.py, 326 lines). Both turn a pair of file trees into sorted ChangeRecord lists; each keeps its own copy of the diff-and-sort policy. Vocabulary: module, interface, depth, seam, locality, leverage, per the codebase-design skill.

A. Deepen diff policy into one diffops seam

Strong

Files: simulate/trace.py, simulate/sandbox.py → new simulate/diffops.py

Problem. Four policy points are duplicated across the two engines, each a copy that can drift: _human_size (verbatim twice), _unified_diff (same algorithm, two signatures), the caps _MAX_DIFF_BYTES = 256 KiB / _MAX_DIFF_CHARS = 4096 (same values, declared twice), and the change ordering _OP_SORT_ORDER plus its (op, path) sort key (declared twice). A bug fixed in one copy - say, the diff truncation rule - silently survives in the other. These helpers are shallow: their interface is nearly as wide as their body, so the seam between the engines hides nothing.

Solution. One deep module, simulate/diffops.py, owning the whole "how a preview renders change" policy behind four names: human_size(n), unified_diff(old, new, rel, *, old_size=None, new_size=None) (sizes optional so both call sites keep their exact semantics), OP_SORT_ORDER, and sort_changes(changes). Both engines import it; their local copies are deleted.

Benefits. Locality: every rule about diff caps, binary fallback, and change ordering lives in one file - reviewing the preview policy means reading one module, not diffing two engines. Leverage: one signature unifies both call shapes without behavior change (OSError paths fall through to None in both). Tests improve: the policy gets one direct test surface (tests/test_diffops.py) instead of being covered twice incidentally through each engine.

B. Unify the two tree walks

Speculative - rejected

Files: _scan_shadow_tree (trace) vs _walk_tree (sandbox)

Both wrap os.walk with an on_error note collector, but the trace walk also resolves tombstone markers against the shim's unlink log - a genuinely different job. Forcing them into one function would build a shallow mega-interface (walk(root, *, tombstones=None, unlink_paths=None, ...)) whose parameter list is as complex as the bodies it hides. Deletion test fails: deleting either walk just moves its complexity next door. Not pursued.

C. Unify the byte comparators

Worth exploring - deferred

Files: _same_bytes (trace) vs filecmp.cmp(shallow=False) (sandbox)

Two implementations of "are these files equal" for the same purpose. Their equality decisions agree on real files today, but filecmp keeps an internal stat cache whose invalidation rules differ from a plain streaming compare. Swapping either side changes no output but touches the engine core; the leverage is small (about 20 lines) and the freeze contract on both engines is strict. Deferred: revisit only if an engine needs to change anyway.

Top recommendation

Do candidate A now

It is the only candidate that passes the deletion test cleanly. The seam is real (two adapters already exist - that makes it a proven seam, not a hypothetical one), the interface shrinks (four names replace eight), and the behavior lock is mechanical: full test suite plus the frozen snapshot manifest sha256=a0894728… must be bit-identical after the change. B is rejected by the deletion test; C is sound but low-leverage and deferred.
